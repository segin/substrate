# Internet protocol suite audit remediation checklist (2026-09-22)

Actionable checklist for every verified finding from the three RFC audits of
the Substrate network stack. Each item names the defect, the site, the fix and
how to verify it, and carries an INCOSE/EARS requirement (`REQ-NETA-nnnn`) in
the section at the end, in the format of the `docs/tasks/` section files
indexed by `TASKS.md`.

| Audit | RFC | Full report | Findings |
|---|---|---|---|
| IPv4 | RFC 791 (`docs/rfc/rfc791.txt`) | `docs/ip-audit-2026-09.md` | pending: audit still running |
| TCP | RFC 793 (`docs/rfc/rfc793.txt`) | `docs/tcp-audit-2026-09.md` | 83: 5 critical, 24 high, 45 medium, 6 low, 3 info |
| UDP | RFC 768 (`docs/rfc/rfc768.txt`) | `docs/udp-audit-2026-09.md` | 53: 2 critical, 14 high, 23 medium, 8 low, 6 info |

IDs are the report IDs prefixed with the protocol (`TCP-MEM-01` is `MEM-01` in
the TCP report), because the two reports reuse the same short IDs. The full
evidence for each item -- the verbatim RFC quote, the code excerpt, the concrete
failure -- is in the report section of the same name.

## How to work this list

Per the `TASKS.md` methodology: take one checkbox at a time, fix it, add or
extend the regression test named under **Verify**, update the man page or spec
the fix touches, tick the box, then commit and push. Kernel changes need
`make -C sys clean` first and a boot test with `--virtio --snapshot`.

Suggested order, highest leverage first:

1. **TCP-MEM-01**: the root cause of TCP-MEM-02, -05, -06, -08 through -13. Fixing
   the lock first makes most of section TCP-A mechanical.
2. **UDP-MEM-01**, **UDP-MEM-02**: kernel memory disclosure and arbitrary kernel
   write, both reachable by any process.
3. **TCP-MEM-03**, **TCP-MEM-04**: use-after-free not covered by the lock fix.
4. **TCP-SM-01**: one lost ACK leaks a PCB, its 32 KiB ring and its port for good.
5. The remaining high items: TCP-SM-02 and TCP-SM-05 together, then TCP-SM-08,
   TCP-HDR-01 together with UDP-U-02/UDP-U-03 (one `ip4_output()` source-address
   change closes all three), then the rest by section.

## UDP (`docs/udp-audit-2026-09.md`)

### UDP-A. Kernel memory safety

- [x] **UDP-MEM-01** (critical) `MSG_TRUNC` makes `copyout()` read past the end of a kernel allocation and into userspace (REQ: REQ-NETA-0001)
    - Site: `sys/net/af_unix.c:1837`
    - Requirement source: none (memory safety)
    - Fix: Clamp in `do_recv()` before the copyout, keeping the byte count produced separate from the `MSG_TRUNC` report: `size_t ncopy = (size_t)n < cap ? (size_t)n : cap;` copy `ncopy`, still `return n;`. The clamp must live in `do_recv()` — fixing only `afinet_recvfrom` would break `MSG_TRUNC` semantics without closing the hole, and would leave the AF_UNIX path open.
    - Verify: recv(fd, buf, 16, MSG_TRUNC) on a 1500-byte datagram returns 1500 and leaves a canary placed after the 16-byte buffer untouched.
- [x] **UDP-MEM-02** (critical) The `recvmsg()` scatter path hands raw user pointers to a kernel sockaddr writer (REQ: REQ-NETA-0002)
    - Site: `sys/net/af_unix.c:2337`
    - Requirement source: none (memory safety)
    - Fix: Stage the source address in a kernel sockaddr buffer in the scatter branch exactly as `do_recv()` does, and copy it out with the same validated sequence, rather than passing `msg_name` and `&umsg->msg_namelen` into `recv_into_kbuf()`.
    - Verify: recvmsg() with two iovecs and msg_name pointing at a kernel address fails with EFAULT and writes nothing; with a valid msg_name it reports the sender.

### UDP-B. RFC 768 conformance

- [ ] **UDP-U-01** (high) A connected UDP socket silently ignores the destination given to `sendto()` (REQ: REQ-NETA-0003)
    - Site: `sys/net/af_inet.c:1281`
    - Requirement source: RFC 768 User Interface
    - Fix: When `addr` is non-NULL on a `SOCK_DGRAM`/`SOCK_RAW` socket, parse and use it even if `s->connected` (POSIX, and what Linux's `udp_sendmsg` does); fall back to the peer only when `addr` is NULL. If BSD-style strictness is preferred, return `-EISCONN` — anything but misdirecting the datagram.
    - Verify: connect() to A, sendto() naming B: the datagram arrives at B (or the call fails EISCONN); A receives nothing.
- [ ] **UDP-U-02** (medium) The source address is not specifiable, and `bind()`'s address is ignored on transmit (REQ: REQ-NETA-0004)
    - Site: `sys/net/af_inet.c:627`
    - Requirement source: RFC 768 User Interface
    - Fix: Give `ip4_output()`/`ip6_output()` an explicit source-address argument, pass `s->local_addr` down from `sys/net/af_inet.c:698` and `:1331` when it is non-wildcard, and use the same value for the pseudo-header in `udp_csum4()` so the two cannot diverge. Fall back to `ip4_source_for()` for a wildcard bind.
    - Note: Same fix as UDP-U-03 and TCP-HDR-01.
    - Verify: Regression case in `tests/sys/torture_udp.c` (or `tests/lib/net/torture_inet.c`) run on target via `tests/run-networking.sh --snapshot`, demonstrating the corrected behaviour.
- [ ] **UDP-U-03** (medium) The checksum's pseudo-header and the IP header are built from two independent, unsynchronised route lookups (REQ: REQ-NETA-0005)
    - Site: `sys/net/af_inet.c:627`
    - Requirement source: RFC 768 Fields/Checksum
    - Fix: Resolve the route once per transmit: have the UDP send path obtain the netdev, use its `ip4_addr` for the pseudo-header, and pass the same netdev/source into `ip4_output()`. That also removes a redundant route lookup from every transmit.
    - Note: Same fix as UDP-U-02 and TCP-HDR-01.
    - Verify: Regression case in `tests/sys/torture_udp.c` (or `tests/lib/net/torture_inet.c`) run on target via `tests/run-networking.sh --snapshot`, demonstrating the corrected behaviour.
- [ ] **UDP-U-04** (low) Destination port 0 is accepted from userland and emitted on the wire (REQ: REQ-NETA-0006)
    - Site: `sys/net/af_inet.c:1288`
    - Requirement source: RFC 768 Fields
    - Fix: Reject a zero destination port with `-EINVAL` in `afinet_sendto_k()` (both family arms, after the `sin_family` check) and in `afinet_connect()` for `SOCK_DGRAM`.
    - Verify: Regression case in `tests/sys/torture_udp.c` (or `tests/lib/net/torture_inet.c`) run on target via `tests/run-networking.sh --snapshot`, demonstrating the corrected behaviour.
- [ ] **UDP-U-05** (low) `sendmsg()` cannot emit a legal zero-payload datagram (REQ: REQ-NETA-0007)
    - Site: `sys/net/af_unix.c:2248`
    - Requirement source: RFC 768 Fields/Length
    - Fix: Treat a datagram socket with a zero total payload as a zero-length datagram: drop the `need == 0` early return, and route `msg_iovlen == 0` on a datagram socket to `sys_sendto_impl(fd, …, 0, …)`.
    - Verify: Regression case in `tests/sys/torture_udp.c` (or `tests/lib/net/torture_inet.c`) run on target via `tests/run-networking.sh --snapshot`, demonstrating the corrected behaviour.
- [ ] **UDP-U-06** (low) `udp_csum6()` leaves `check == 0` when source selection fails (REQ: REQ-NETA-0008)
    - Site: `sys/net/af_inet.c:637`
    - Requirement source: RFC 8200 8.1
    - Fix: Make `udp_csum6` return int and have both callers abort the send with `-ENETUNREACH` on failure. Better, resolve the route and source once and pass the chosen netdev/source down to `ip6_output` so the two lookups cannot disagree (same shape as the U-03 fix).
    - Verify: Regression case in `tests/sys/torture_udp.c` (or `tests/lib/net/torture_inet.c`) run on target via `tests/run-networking.sh --snapshot`, demonstrating the corrected behaviour.
- [ ] **UDP-I-01** (info) No IP reassembly: the usable Length range is 8..1480, not 8..65535 (REQ: REQ-NETA-0009)
    - Site: `sys/net/inet.c:308`
    - Requirement source: RFC 768 Fields/Length
    - Fix: Implement reassembly with a bounded queue and a timeout, and raise the socket ceiling once it exists. As an interim measure bump `dev->rx_dropped` at the fragment drop so the loss is observable.
    - Verify: Regression case in `tests/sys/torture_udp.c` (or `tests/lib/net/torture_inet.c`) run on target via `tests/run-networking.sh --snapshot`, demonstrating the corrected behaviour.

### UDP-C. ICMP error handling

- [ ] **UDP-ICMP-01** (high) ICMP errors never reach a UDP socket, and `SO_ERROR` is hardcoded 0 (REQ: REQ-NETA-0010)
    - Site: `sys/net/icmp.c:32`, `sys/net/af_inet.c:1168`
    - Requirement source: RFC 1122 4.1.3.3
    - Fix: Handle types 3/4/11/12 in `icmp_input()`: parse the quoted IP header plus the first 8 bytes of the offending transport header (for UDP that is the whole `udphdr`, giving the 4-tuple), map it to the originating socket, latch an errno (`ECONNREFUSED` for code 3, `EHOSTUNREACH`/`ENETUNREACH` for codes 0-1, `EMSGSIZE` for code 4) in a new `afi_sock_t::so_error` that `afinet_so_error()` returns and clears, and wake any blocked reader.
    - Verify: Send to a closed port on a peer that returns Port Unreachable; the next recv() fails ECONNREFUSED and SO_ERROR reports it once.
- [ ] **UDP-ICMP-02** (medium) No ICMP Port Unreachable for an unmatched port — the `delivered` result is computed and thrown away (REQ: REQ-NETA-0011)
    - Site: `sys/net/udp.c:49`
    - Requirement source: RFC 1122 4.1.3.1
    - Fix: Capture the return at `sys/net/udp.c:49` and `:55` and, when it is 0, emit type 3 code 3 (v4) or ICMPv6 type 1 code 4 quoting the IP header plus the first 8 octets. Suppress it for broadcast and multicast destinations and rate-limit it (RFC 1122 3.2.2) — `ip4_input` already computes `for_bcast` at `sys/net/inet.c:338` but does not pass it down to `udp_input`, so that flag needs plumbing through.
    - Verify: Regression case in `tests/sys/torture_udp.c` (or `tests/lib/net/torture_inet.c`) run on target via `tests/run-networking.sh --snapshot`, demonstrating the corrected behaviour.

### UDP-D. IP transmit and receive, as seen by UDP

- [ ] **UDP-IP-01** (high) Outbound datagram size is bounded by a compile-time constant, not the egress MTU, and the stack never fragments (REQ: REQ-NETA-0012)
    - Site: `sys/net/inet.c:231`
    - Requirement source: RFC 791 / RFC 1122 3.3.3
    - Fix: Take the MTU from the netdev `route_for_v4`/`route_for_v6` already returned and either fragment, or return `-EMSGSIZE` when `sizeof(iphdr) + payload_len > dev->mtu`. Bound `eth_send` by `dev->mtu` too. Until fragmentation exists, derive the socket layer's per-send gate from the route's MTU rather than from `AFI_DATA_MAX`, so `sendto()` fails loudly instead of emitting an uncarriable frame.
    - Verify: sendto() of MTU-20 bytes of UDP payload over a 1500-MTU interface either arrives fragmented at the peer or fails EMSGSIZE; tcpdump on the host shows no oversize frame.
- [ ] **UDP-IP-02** (high) Only 127.0.0.1 and 127.255.255.255 of 127/8 are deliverable (REQ: REQ-NETA-0013)
    - Site: `sys/net/inet.c:340`
    - Requirement source: RFC 1122 3.2.1.3(g)
    - Fix: In `ip4_input`, accept when the receiving device is `NETDEV_IFF_LOOPBACK` and `(ntohl(ih->daddr) >> 24) == 127`, alongside the exact-address and broadcast tests. The martian-source filter already assumes exactly that model.
    - Verify: A UDP datagram sent to 127.0.0.2 reaches a socket bound to 0.0.0.0.
- [ ] **UDP-IP-03** (high) A datagram to the host's own NIC address is ARPed for on the wire and fails `EHOSTUNREACH` (REQ: REQ-NETA-0014)
    - Site: `sys/net/inet.c:256`
    - Requirement source: RFC 1122 3.3.4.2
    - Fix: Before the subnet scan in `route_for_v4`, test `daddr` against every registered netdev's `ip4_addr`; on a match return the loopback device with `*via_gw_out = 0`, and have `ip4_input` accept a destination equal to any local interface address when the frame arrives on `lo`. Mirror it in `route_for_v6`/`ip6_input`.
    - Verify: sendto() the host's own NIC address reaches a local socket; no ARP request appears on the wire.
- [ ] **UDP-IP-04** (high) Limited broadcast 255.255.255.255 is unicast to the default gateway (REQ: REQ-NETA-0015)
    - Site: `sys/net/inet.c:158`
    - Requirement source: RFC 1122 3.3.6
    - Fix: Add a first arm to `route_for_v4` for `daddr == 0xFFFFFFFF` selecting the first UP, non-loopback `NETDEV_IFF_BROADCAST` device with `via_gw = 0`, and short-circuit next-hop resolution for it (IP-05).
    - Verify: Capture on the host shows the frame with destination MAC ff:ff:ff:ff:ff:ff.
- [ ] **UDP-IP-05** (high) Directed broadcast is ARPed for — which fails, and lets any on-link host capture all of our broadcast traffic for five minutes (REQ: REQ-NETA-0016)
    - Site: `sys/net/inet.c:256`, `sys/net/arp.c:194`
    - Requirement source: RFC 1122 3.3.6 / RFC 826
    - Fix: Before the `arp_lookup` in `ip4_output`, test the destination against `0xFFFFFFFF` and against `(dev->ip4_addr & dev->ip4_netmask) | ~dev->ip4_netmask`; on a match set the MAC to `ff:ff:ff:ff:ff:ff` and skip resolution, mirroring `sys/net/inet6.c:269-273`. Additionally, refuse to insert a cache entry whose IP is 255.255.255.255, a link broadcast address, or in 224/4, in `arp_insert_raw` (`sys/net/arp.c:107`).
    - Note: Pairs with UDP-IP-04.
    - Verify: A gratuitous ARP reply for the subnet broadcast address is ignored and broadcasts still go to ff:ff:ff:ff:ff:ff.
- [ ] **UDP-IP-06** (high) IPv4 multicast is absent end to end (REQ: REQ-NETA-0017)
    - Site: `sys/net/inet.c:255/340`
    - Requirement source: RFC 1112 / RFC 1122 3.3.7
    - Fix: Add a Class D arm to `route_for_v4` (direct, `via_gw = 0`, on the first UP multicast-capable device); add a branch in `ip4_output` before `sys/net/inet.c:254` building `mac = {0x01,0x00,0x5e, b1 & 0x7f, b2, b3}`; extend the accept test at `sys/net/inet.c:336-342` with a Class D branch gated on a real membership list (always accepting 224.0.0.1, per RFC 1122 3.3.7); add a per-socket group list to `afi_sock_t` and a per-interface list to `netdev_t` with a `set_rx_mode` op in `struct netdev_ops`; and give `ip4_output` a `ttl` argument defaulting to 1 for Class D.
    - Verify: Join 239.1.2.3 on target; a host-side sender's datagram to that group is received.
- [ ] **UDP-IP-07** (medium) An interface with no IPv4 address cannot transmit at all, so UDP DHCP cannot bootstrap (REQ: REQ-NETA-0018)
    - Site: `sys/net/inet.c:173`
    - Requirement source: RFC 2131 4.1
    - Fix: Let the limited-broadcast route select an UP, non-loopback `NETDEV_IFF_BROADCAST` device regardless of `ip4_addr`, and let `ip4_output` emit `saddr` 0.0.0.0 in that case.
    - Note: Depends on UDP-IP-04.
    - Verify: Regression case in `tests/sys/torture_udp.c` (or `tests/lib/net/torture_inet.c`) run on target via `tests/run-networking.sh --snapshot`, demonstrating the corrected behaviour.
- [ ] **UDP-IP-08** (medium) A broadcast datagram is delivered to exactly one socket (REQ: REQ-NETA-0019)
    - Site: `sys/net/af_inet.c:1675`
    - Requirement source: RFC 1122 3.3.6
    - Fix: Pass a "destination was broadcast/multicast" flag from `ip4_input`/`ip6_input` through `udp_input` into `afinet_deliver_v*` and, in that case, enqueue a copy into every socket whose `sock_score()` ≥ 0, keeping best-match selection for unicast.
    - Verify: Regression case in `tests/sys/torture_udp.c` (or `tests/lib/net/torture_inet.c`) run on target via `tests/run-networking.sh --snapshot`, demonstrating the corrected behaviour.
- [ ] **UDP-IP-09** (medium) `ip6_input` accepts every IPv6 multicast group, with no membership check and a comment claiming otherwise (REQ: REQ-NETA-0020)
    - Site: `sys/net/inet6.c:327`
    - Requirement source: RFC 4291 / RFC 1122 3.3.7
    - Fix: Replace the blanket `h->dst[0] == 0xff` accept with an explicit test against the interface's solicited-node address and `ff02::1`, plus a real membership list once one exists, and fix the comment at `sys/net/inet6.c:323-324`.
    - Verify: Regression case in `tests/sys/torture_udp.c` (or `tests/lib/net/torture_inet.c`) run on target via `tests/run-networking.sh --snapshot`, demonstrating the corrected behaviour.
- [ ] **UDP-IP-10** (medium) UDP over IPv6 is undeliverable behind any extension header (REQ: REQ-NETA-0021)
    - Site: `sys/net/inet6.c:332`
    - Requirement source: RFC 8200 §4, §8.1
    - Fix: Walk past Hop-by-Hop/Routing/Destination Options/Fragment to the first upper-layer header and pass the resulting protocol, adjusted payload pointer/length and (with a Routing header) final destination to `udp_input`. Unrecognised Next Header values should produce an ICMPv6 Parameter Problem, not a silent drop.
    - Verify: Regression case in `tests/sys/torture_udp.c` (or `tests/lib/net/torture_inet.c`) run on target via `tests/run-networking.sh --snapshot`, demonstrating the corrected behaviour.
- [ ] **UDP-IP-11** (low) `lo` advertises MTU 16384; `lo_xmit` truncates at 1700 and reports success (REQ: REQ-NETA-0022)
    - Site: `sys/net/loopback.c:75`
    - Requirement source: RFC 1122 3.3.3
    - Fix: Set `lo_netdev.mtu` to a value the path can carry, and make `lo_xmit` return `-EMSGSIZE` for `len > LO_FRAME_MAX` instead of truncating and reporting success.
    - Verify: Regression case in `tests/sys/torture_udp.c` (or `tests/lib/net/torture_inet.c`) run on target via `tests/run-networking.sh --snapshot`, demonstrating the corrected behaviour.

### UDP-E. Socket API

- [ ] **UDP-API-01** (high) Any unprivileged process can steal a bound UDP port (REQ: REQ-NETA-0023)
    - Site: `sys/net/af_inet.c:899`
    - Requirement source: BSD/POSIX port ownership
    - Fix: Require the incumbent to have set `SO_REUSEADDR` too, and require matching euid, before allowing a duplicate bind; reject `bind()` to a port < 1024 unless `current_process->euid == 0`; and when duplicate binds are legitimately permitted, make the tie-break deterministic and documented rather than "most recently created wins".
    - Note: The reserved-port half is shared with TCP-API-18 (same `afinet_bind()`).
    - Verify: As root bind 0.0.0.0:53; as an unprivileged user bind 0.0.0.0:53 fails EACCES, and a same-user duplicate without SO_REUSEADDR on both fails EADDRINUSE.
- [ ] **UDP-API-02** (high) Multi-iovec `sendmsg()` on a UDP socket always fails `EFAULT` (REQ: REQ-NETA-0024)
    - Site: `sys/net/af_unix.c:2260`
    - Requirement source: POSIX `sendmsg(2)`
    - Fix: Plumb `kernel_payload` through the AF_PACKET/AF_INET/AF_INET6 routes — an `afinet_sendto_kbuf()` entry (or a flag) that skips the `copyin` and calls `afinet_sendto_k()` directly with the gather buffer.
    - Verify: Two-iovec sendmsg() on UDP returns the total length and one datagram arrives with the concatenated payload.
- [ ] **UDP-API-03** (high) `writev(2)` on a connected UDP socket emits one datagram per iovec (REQ: REQ-NETA-0025)
    - Site: `sys/exec/perso/compat.c:572`
    - Requirement source: POSIX `writev(2)`
    - Fix: Give `sys_writev` and `linux_sys_do_uio` the SOCK-04 treatment: when `sock_fd_is_dgram(fd)` and `iovcnt > 1`, gather into one kernel buffer and issue a single write, returning `EMSGSIZE` if the total exceeds the datagram cap. Factor the existing gather in `sys/net/af_unix.c:2245-2266` into a shared helper rather than duplicating it a third time.
    - Verify: writev() of three iovecs on connected UDP delivers one datagram of the summed length.
- [ ] **UDP-API-04** (high) `SO_RCVTIMEO`/`SO_SNDTIMEO` are accepted and discarded; the blocking receive loop has no deadline (REQ: REQ-NETA-0026)
    - Site: `sys/net/af_inet.c:1531`
    - Requirement source: POSIX `SO_RCVTIMEO`
    - Fix: Add `rcv_timeo`/`snd_timeo` (ticks, 0 = none) to `afi_sock_t`, populate them from `sys_setsockopt` (struct timeval, `copyin`), give `afi_wait` an absolute-deadline argument — the `sys/kern/futex.c:476` and `sys/kern/posix_mqueue.c:221-234` paths already show the `sleep_expiry` pattern — and return `-EAGAIN` when the deadline passes with an empty ring. Answer `getsockopt` from the stored value instead of `-ENOPROTOOPT`.
    - Verify: SO_RCVTIMEO=200 ms on an idle UDP socket: recv() returns EAGAIN after ~200 ms.
- [ ] **UDP-API-05** (high) The socket-option surface is hardcoded to Linux numbering, so every option from a BSD-personality program is discarded (REQ: REQ-NETA-0027)
    - Site: `sys/net/af_unix.c:2607`
    - Requirement source: POSIX `setsockopt(2)`
    - Fix: Canonicalise level/optname at the personality boundary (a small table in `perso_freebsd.c`/`perso_netbsd.c`/`perso_openbsd.c`), or have `sys_setsockopt`/`sys_getsockopt` canonicalise from `current_process`'s personality before the tests at `sys/net/af_unix.c:2607` and `:2648`. Returning `-ENOPROTOOPT` instead of 0 for unrecognised levels would at least make the failure visible.
    - Verify: A FreeBSD-personality program setting SO_REUSEADDR and SO_RCVTIMEO sees them take effect.
- [ ] **UDP-API-06** (medium) `bind()` accepts any address, so a socket bound to a non-local address is permanently dead with no error (REQ: REQ-NETA-0028)
    - Site: `sys/net/af_inet.c:910`
    - Requirement source: RFC 1122 3.2.1.3
    - Fix: When `sin_addr` is non-zero, walk `netdev_first()`/`netdev_next()` and require a match against a device's `ip4_addr` (or its broadcast address, or 127/8 once IP-02 is fixed); return `-EADDRNOTAVAIL` otherwise. Same for the AF_INET6 branch at `sys/net/af_inet.c:925`.
    - Note: Accepting 127/8 depends on UDP-IP-02.
    - Verify: Regression case in `tests/sys/torture_udp.c` (or `tests/lib/net/torture_inet.c`) run on target via `tests/run-networking.sh --snapshot`, demonstrating the corrected behaviour.
- [ ] **UDP-API-07** (medium) `connect()` on a UDP socket assigns no local port (REQ: REQ-NETA-0029)
    - Site: `sys/net/af_inet.c:1253`
    - Requirement source: BSD/POSIX `connect(2)`
    - Fix: In `afinet_connect()`, for a `SOCK_DGRAM` socket with `s->local_port == 0`, allocate via `afinet_alloc_ephemeral_free()` and set `s->bound = 1` before returning, and fill `s->local_addr` from `ip4_source_for(peer)`/`ip6_source_for(peer)`.
    - Verify: Regression case in `tests/sys/torture_udp.c` (or `tests/lib/net/torture_inet.c`) run on target via `tests/run-networking.sh --snapshot`, demonstrating the corrected behaviour.
- [ ] **UDP-API-08** (medium) `recv()` ignores `shutdown(SHUT_RD)` and blocks forever while `read()` returns EOF (REQ: REQ-NETA-0030)
    - Site: `sys/net/af_inet.c:1426`
    - Requirement source: POSIX `shutdown(2)`
    - Fix: Test `s->rd_shut` in `afinet_recvfrom` at entry and after each `afi_wait()` wake, returning 0, matching `afinet_node_read_body:564`; report `POLLIN|POLLRDHUP` from `afinet_node_poll` when it is set.
    - Verify: Regression case in `tests/sys/torture_udp.c` (or `tests/lib/net/torture_inet.c`) run on target via `tests/run-networking.sh --snapshot`, demonstrating the corrected behaviour.
- [ ] **UDP-API-09** (medium) A zero-length receive does not consume the datagram, so a `poll()`-driven drain loop spins (REQ: REQ-NETA-0031)
    - Site: `sys/net/af_unix.c:1821`
    - Requirement source: POSIX `recv(2)`
    - Fix: Move the `len == 0` short-circuit out of the datagram path: for `SOCK_DGRAM`, let the call reach `afinet_recvfrom()` with `len` 0 so the datagram is dequeued (unless `MSG_PEEK`), the source address is reported and `MSG_TRUNC` returns `p->truelen`. Keep the early return for stream sockets.
    - Verify: Regression case in `tests/sys/torture_udp.c` (or `tests/lib/net/torture_inet.c`) run on target via `tests/run-networking.sh --snapshot`, demonstrating the corrected behaviour.
- [ ] **UDP-API-10** (medium) EOF leaves `*addrlen` at the 128-byte kernel bounce capacity (REQ: REQ-NETA-0032)

    - Verify: Regression case in `tests/lib/net/torture_net.c` / `torture_tcp_net` (with `tcp_partner.c` where a remote peer is needed) run via `tests/run-networking.sh --snapshot`, demonstrating the corrected behaviour.
- [ ] **TCP-RES-02** (medium) `tcp_close()`'s LISTEN arm emits a RST per child inline under the same lock (REQ: REQ-NETA-0132)
    - Site: `sys/net/tcp.c:1670`
    - Requirement source: none (latency)
    - Fix: Same shape as RES-01: under the lock, mark each child detached and bump its `holds`, build a bounded list, drop the lock, then send the RSTs with interrupts enabled and release the holds. The hold is what makes it safe against the reaper, which is precisely the race A45 describes.

## User Stories

- **US-NETA-01** (UDP-A, Kernel memory safety): As a Substrate user running untrusted programs, I want UDP receive paths never to disclose or overwrite kernel memory, so that a local process or remote sender cannot compromise the kernel. Covers REQ-NETA-0001..REQ-NETA-0002.
- **US-NETA-02** (UDP-B, RFC 768 conformance): As an application author, I want UDP to behave as RFC 768 specifies, so that datagrams go where I address them and carry checksums peers accept. Covers REQ-NETA-0003..REQ-NETA-0009.
- **US-NETA-03** (UDP-C, ICMP error handling): As an application author, I want ICMP errors reflected in socket errors and generated for unreachable ports, so that failures surface immediately instead of as timeouts. Covers REQ-NETA-0010..REQ-NETA-0011.
- **US-NETA-04** (UDP-D, IP transmit and receive, as seen by UDP): As a network administrator, I want loopback, broadcast, multicast and MTU handling to follow the host requirements, so that DHCP, discovery protocols and local services work. Covers REQ-NETA-0012..REQ-NETA-0022.
- **US-NETA-05** (UDP-E, Socket API): As a porter of Linux and BSD software, I want the UDP socket API to follow POSIX semantics and errno conventions, so that existing programs run without Substrate-specific workarounds. Covers REQ-NETA-0023..REQ-NETA-0042.
- **US-NETA-06** (UDP-F, Resources and accounting): As an operator, I want UDP buffering bounded by bytes and every drop counted, so that load is predictable and packet loss is diagnosable. Covers REQ-NETA-0043..REQ-NETA-0048.
- **US-NETA-07** (UDP-G, Informational / decision items): As a maintainer, I want deliberate deviations recorded with their re-audit triggers, so that enabling a feature later does not silently expose unexercised code. Covers REQ-NETA-0049..REQ-NETA-0053.
- **US-NETA-08** (TCP-A, Concurrency and memory safety): As a Substrate user, I want TCP connection state protected against concurrent access, so that loopback and network traffic cannot corrupt or use freed kernel memory. Covers REQ-NETA-0054..REQ-NETA-0066.
- **US-NETA-09** (TCP-B, State machine (RFC 793 3.4, 3.5, 3.9)): As an application author, I want the TCP state machine to follow RFC 793 (as amended by RFC 5961), so that connections open, close and survive blind attacks the way peers expect. Covers REQ-NETA-0067..REQ-NETA-0081.
- **US-NETA-10** (TCP-C, Window management, reliability and congestion (RFC 793 3.7)): As a user moving bulk data, I want correct window management, persist probing and retransmission, so that transfers neither stall nor abort on healthy paths. Covers REQ-NETA-0082..REQ-NETA-0095.
- **US-NETA-11** (TCP-D, Wire header and sequence numbers (RFC 793 3.1, 3.3)): As an application author, I want correct checksums, option handling and MSS negotiation, so that connections interoperate with any conforming peer. Covers REQ-NETA-0096..REQ-NETA-0100.
- **US-NETA-12** (TCP-E, Urgent mechanism): As a porter of telnet/ftp/rlogin-style software, I want urgent data to work or fail explicitly, so that out-of-band signalling is never silently lost. Covers REQ-NETA-0101..REQ-NETA-0106.
- **US-NETA-13** (TCP-F, User interface and connection identity (RFC 793 3.8, 2.7)): As an application author, I want connect/bind/listen/accept/send/close to follow POSIX semantics mapped onto RFC 793, so that error handling in existing programs works. Covers REQ-NETA-0107..REQ-NETA-0130.
- **US-NETA-14** (TCP-G, Interrupt latency and resource handling): As an operator, I want TCP housekeeping to run without long interrupts-off windows and with O(1) lookup, so that the system stays responsive under load. Covers REQ-NETA-0131..REQ-NETA-0135.
- **US-NETA-15** (TCP-H, Precedence and security (RFC 793 3.6)): As a maintainer, I want the absence of RFC 793 precedence/security stated explicitly, so that the omission is a decision rather than an oversight. Covers REQ-NETA-0136.
