# Substrate BSD personality audit (2026-07-23)

Auditors cross-referenced substrate's FreeBSD/NetBSD/OpenBSD translation layers against the real source trees at `~/freebsd` and `~/netbsd`; every finding cites the real BSD source line and was independently verified against it. **26 findings, all 26 confirmed** (1 critical, 12 high, 5 medium, 8 low).


## CRITICAL

### P01. Signal syscalls route through native dispatch with NO BSD-to-native signal-number/mask translation
- **Substrate:** `sys/exec/perso/perso_openbsd.c:130`  ·  missing-translation  ·  CONFIRMED
- **BSD reference:** /home/segin/netbsd/sys/sys/signal.h:72 (SIGCHLD 20), :82 (SIGUSR1 30), :83 (SIGUSR2 31), :62 (SIGBUS 10), :69 (SIGSTOP 17), :71 (SIGCONT 19) — confirmed identical in /home/segin/freebsd/sys/sys/signal.h:109/127/91/106
- **Defect:** The OpenBSD table binds sigaction (line 130), kill (121), sigprocmask (132) directly to the native sys_* entry points, and openbsd_sendsig()/openbsd_sys_sigreturn() copy `sig` and `sc_mask` verbatim (openbsd_sig.c:26,46,84). OpenBSD uses the historical 4.3BSD signal numbering (SIGCHLD=20, SIGUSR1=30, SIGUSR2=31, SIGBUS=10, SIGSTOP=17, SIGCONT=19, SIGSYS=12) whereas substrate-native is Linux-ish (SIGCHLD=17, SIGUSR1=10, SIGBUS=7, SIGSTOP=19). The sibling NetBSD personality (netbsd_sig.c) performs full signo + sigmask + sa_flags translation for exactly this reason and documents that skipping it wedges ksh job control. The OpenBSD personality does none of it.
- **Breaks:** An OpenBSD binary calling sigaction(SIGCHLD=20, ...) installs the handler on native slot 20 (SIGTSTP); the kernel raises native SIGCHLD=17, for which the program registered nothing, so shells/job-control block forever in the equivalent of sigsuspend and child reaping never fires. sa_mask bit positions (bit signo-1) are likewise mis-numbered, and the mask restored on sigreturn is wrong.


## HIGH

### P02. BSD errno translation table omits the entire socket/network errno range (and EINPROGRESS/EALREADY/EOVERFLOW/ESTALE/EIDRM/ENOMSG), returning Linux-numbered errnos to NetBSD binaries
- **Substrate:** `sys/arch/i386/syscall.c:52`  ·  errno-signo  ·  CONFIRMED
- **BSD reference:** /home/segin/netbsd/sys/sys/errno.h:83 EINPROGRESS=36, :84 EALREADY=37, :97 ENOTSOCK=38, :98 EADDRINUSE=48 (grep line), :112 ECONNREFUSED=61, :107 EISCONN=56, :108 ENOTCONN=57, :105 ECONNRESET=54, :119 EHOSTUNREACH=65, :128 ESTALE=70, :146 EOVERFLOW=84 — vs substrate/Linux numbering in /home/segin/substrate/include/errno.h (ENOTSOCK=88, EADDRINUSE=98, ECONNREFUSED=111, EISCONN=106, EINPROGRESS=115, EALREADY=114, ETIMEDOUT already handled, EOVERFLOW=75, ESTALE=116)
- **Defect:** bsd_errno_xlate() (sys/arch/i386/syscall.c:52-64) is the single point that maps substrate's Linux-numbered errnos to BSD numbering for the FreeBSD/NetBSD/OpenBSD personalities (applied to every syscall return at line 537). It only special-cases EAGAIN, EDEADLK, ENOSYS, ENOTEMPTY, EOPNOTSUPP, ETIMEDOUT, EOWNERDEAD, ENOTRECOVERABLE; everything else falls through 'default: return e'. But the whole BSD socket/network errno block (values 36..70 on NetBSD) lives at 88..116 in substrate's Linux numbering, so it is passed through unchanged: EINPROGRESS 115 vs NetBSD 36, EALREADY 114 vs 37, ENOTSOCK 88 vs 38, EDESTADDRREQ 89 vs 39, EMSGSIZE 90 vs 40, EPROTOTYPE 91 vs 41, ENOPROTOOPT 92 vs 42, EPROTONOSUPPORT 93 vs 43, ESOCKTNOSUPPORT 94 vs 44, EPFNOSUPPORT 96 vs 46, EAFNOSUPPORT 97 vs 47, EADDRINUSE 98 vs 48, EADDRNOTAVAIL 99 vs 49, ENETDOWN 100 vs 50, ENETUNREACH 101 vs 51, ENETRESET 102 vs 52, ECONNABORTED 103 vs 53, ECONNRESET 104 vs 54, ENOBUFS 105 vs 55, EISCONN 106 vs 56, ENOTCONN 107 vs 57, ESHUTDOWN 108 vs 58, ECONNREFUSED 111 vs 61, EHOSTDOWN 112 vs 64, EHOSTUNREACH 113 vs 65, ESTALE 116 vs 70; plus EOVERFLOW 75 vs 84, EIDRM 43 vs 82, ENOMSG 42 vs 83. These are wired to native handlers (sys_connect/sys_bind/sys_accept/... in the netbsd syscall table) whose failures produce exactly these errnos. NetBSD libc/programs interpret the raw substrate numbers against their own <errno.h>, so the value is silently wrong (e.g. NetBSD errno 115 is undefined; 98 reads as nothing standard; 111 is out of range).
- **Breaks:** A NetBSD i386 binary opens a non-blocking socket and calls connect(); the kernel returns substrate EINPROGRESS=115, but NetBSD libc/the program compares errno against its EINPROGRESS=36, so the in-progress connect is misread as a hard failure (or an unknown errno) and the connection is aborted instead of completing via poll/select. Likewise bind() on a busy port returns 98 where the program expects EADDRINUSE=48, and a refused connect returns 111 where the program expects ECONNREFUSED=61 — so retry/'address in use'/'connection refused' logic in any networked NetBSD program (and stat/lseek EOVERFLOW handling on >2GB files: 75 vs 84) behaves incorrectly.

### P03. EOVERFLOW is not translated to the BSD number (falls through as EPROGMISMATCH)
- **Substrate:** `sys/arch/i386/syscall.c:62`  ·  errno-signo  ·  CONFIRMED
- **BSD reference:** /home/segin/freebsd/sys/sys/errno.h:164 (EOVERFLOW 84) and /home/segin/freebsd/sys/sys/errno.h:151 (EPROGMISMATCH 75); /home/segin/netbsd/sys/sys/errno.h:146 (EOVERFLOW 84) and /home/segin/netbsd/sys/sys/errno.h:133 (EPROGMISMATCH 75)
- **Defect:** bsd_errno_xlate() (sys/arch/i386/syscall.c:52-64) is the single errno translation table applied to every FreeBSD/NetBSD/OpenBSD syscall error return (used at line 537 and 250). Substrate-native EOVERFLOW is 75 (sys/include/sys/errno.h:49), but on both FreeBSD and NetBSD EOVERFLOW is 84 and value 75 is EPROGMISMATCH. The switch has no case for EOVERFLOW, so it hits the `default: return e;` at line 62 and hands the foreign program 75 unchanged. Substrate actually returns -EOVERFLOW to userland from the mmap offset-overflow paths (sys/vm/vm_syscalls.c:282 and :293), which are directly reachable by a BSD binary's mmap(2). The BSD libc/program therefore sees errno EPROGMISMATCH (an RPC error) instead of the POSIX-mandated EOVERFLOW. Fix: add `case EOVERFLOW: return 84;`.
- **Breaks:** A FreeBSD or NetBSD i386 binary calls mmap(2) with an offset whose page-shifted value overflows (POSIX requires EOVERFLOW). Substrate returns -EOVERFLOW (75); bsd_errno_xlate leaves it 75; the BSD stub sets errno=75 which decodes to EPROGMISMATCH. Any `if (errno == EOVERFLOW)` retry/fallback logic misfires, and error messages print 'RPC version wrong' / 'Program version wrong' nonsense.

### P04. Kernel-generated signals delivered to FreeBSD processes are not number-translated (SIGCHLD/SIGTSTP/SIGBUS mismatch)
- **Substrate:** `sys/exec/perso/freebsd/freebsd_sig.c:227`  ·  errno-signo  ·  CONFIRMED
- **BSD reference:** /home/segin/freebsd/sys/sys/signal.h:107 (SIGTSTP=18), :109 (SIGCHLD=20), :91 (SIGBUS=10) vs substrate sys/include/sys/signal.h:52 (SIGCHLD=17), :55 (SIGTSTP=20), :42 (SIGBUS=7)
- **Defect:** freebsd_sys_sigaction() forwards the FreeBSD signal number straight to kern_sigaction(sig,...) with an explicit comment that numbers are left untranslated to stay 'self-consistent' with kill/thr_kill. But the kernel itself posts signals using native (Linux-numbered) constants: sys/pm/process.c:1839/1850 and sys/kern/signal.c:1027/1293 call psignal(parent, SIGCHLD) with native SIGCHLD=17, and sys/drivers/console/tty.c:695 sends native SIGTSTP=20. The dispatch (signal.c:1838) hands the native number to the personality sendsig with no native->FreeBSD remap. sig_actions is indexed by number, so a FreeBSD handler installed for SIGCHLD sits at native slot 20 while the kernel posts to slot 17. FreeBSD numbers only coincide with native for SIGINT/SIGQUIT/SIGILL/SIGFPE/SIGSEGV/SIGPIPE/SIGALRM/SIGWINCH; they differ for SIGCHLD, SIGTSTP, SIGCONT, SIGSTOP, SIGBUS, SIGSYS, SIGUSR1, SIGUSR2.
- **Breaks:** A FreeBSD program installs a SIGCHLD (FreeBSD #20) handler for async child reaping (e.g. sh job control, an event loop). When a child exits, the kernel posts native SIGCHLD=17 to slot 17 (empty -> default ignore), so the handler never runs. Worse, pressing Ctrl-Z sends native SIGTSTP=20, which lands in native slot 20 -- exactly where the FreeBSD app's SIGCHLD handler was installed -- so a terminal suspend spuriously invokes the child-reaping handler. Similarly a bus-error fault (native SIGBUS=7) reaches a FreeBSD handler installed for #7 (FreeBSD SIGEMT), not its SIGBUS (#10) handler.

### P05. FreeBSD personality never translates BSD<->native signal numbers (kernel-generated signals hit the wrong handler slot)
- **Substrate:** `sys/exec/perso/freebsd/freebsd_sig.c:73`  ·  missing-translation  ·  CONFIRMED
- **BSD reference:** /home/segin/freebsd/sys/sys/signal.h:109 (SIGCHLD 20), :127 (SIGUSR1 30), :91 (SIGBUS 10) — all differ from substrate native (SIGCHLD 17, SIGUSR1 10, SIGBUS 7 in sys/include/sys/signal.h)
- **Defect:** freebsd_sendsig() passes `sig` straight into frame.sf_signum (line 73) and freebsd_sys_sigaction() (lines 214-238) installs handlers on the raw number, with an explicit comment (lines 205-213) stating numbers are 'deliberately left untranslated'. But the shared kernel signal machinery uses NATIVE numbers: signal.c:1838 hands freebsd_sendsig the native `sig`, and the NetBSD personality in the same tree DOES translate (netbsd_sig.c:173 native_to_netbsd_signo) precisely because the numberings diverge. FreeBSD i386 uses the 4.3BSD numbering (SIGCHLD=20, SIGUSR1=30, SIGUSR2=31, SIGBUS=10, SIGSYS=12, SIGSTOP=17/SIGTSTP=18/SIGCONT=19) which differs from substrate native (SIGCHLD=17, SIGUSR1=10, SIGUSR2=12, SIGBUS=7, SIGSYS=31, SIGSTOP=19/SIGTSTP=20/SIGCONT=18). No translation function exists anywhere in the FreeBSD personality.
- **Breaks:** A FreeBSD binary (any shell, make, init-style reaper) calls sigaction(SIGCHLD=20, handler); substrate installs it on native slot 20. When a child exits the kernel raises native SIGCHLD=17, which lands on native slot 17 (no handler -> default/ignored), so the FreeBSD handler on slot 20 never fires and child reaping / job control silently breaks. Symmetrically, TTY-generated native SIGTSTP=20 fires the program's slot-20 handler with signum=20, which the FreeBSD program interprets as SIGCHLD. SIGUSR1/2, SIGBUS, SIGSYS handlers are all misrouted the same way. This is the exact bug the NetBSD personality's translation comment (netbsd_sig.c:12-32) says causes ksh to block forever in sigsuspend.

### P06. setgid(2) mapped to syscall 46 instead of 181 — modern setgid unhandled, old sigaction slot misrouted
- **Substrate:** `sys/exec/perso/freebsd/freebsd_syscalls.h:54`  ·  wrong-syscall-number  ·  CONFIRMED
- **BSD reference:** /home/segin/freebsd/sys/sys/syscall.h:174 (#define SYS_setgid 181); syscall.h:53 ("46 is old sigaction")
- **Defect:** FREEBSD_SYS_setgid is defined as 46, and perso_freebsd.c wires [FREEBSD_SYS_setgid]=&sys_setgid at that index. On FreeBSD, syscall 46 is the obsolete COMPAT sigaction and the real setgid(2) is syscall 181. The table has no entry at 181, so a modern FreeBSD i386 binary calling setgid(2) (number 181) lands on an empty slot and gets ENOSYS, while any invocation of the legacy sigaction slot (46) would instead run sys_setgid.
- **Breaks:** A FreeBSD daemon or login/su program that drops group privileges via setgid() issues syscall 181; the personality table has nothing at 181, the call fails with ENOSYS, and the program either aborts or continues running with elevated group credentials (privilege-drop failure).

### P07. freebsd13_stat timestamps use 64-bit tv_sec + omit __STAT_TIME_T_EXT words, so every st_atim/mtim/ctim/birthtim seconds field reads as 0 on real i386 FreeBSD binaries
- **Substrate:** `sys/exec/perso/freebsd/freebsd_user.h:205`  ·  struct-layout  ·  CONFIRMED
- **BSD reference:** /home/segin/freebsd/sys/sys/stat.h:155-192 (struct stat: __STAT_TIME_T_EXT defined for __i386__ at 155-157, and st_atim_ext/st_mtim_ext/st_ctim_ext/st_btim_ext 4-byte words interleaved before each `struct timespec` at 169-184); /home/segin/freebsd/sys/x86/include/_types.h:80 (i386 __time_t = __int32_t, so struct timespec is 8 bytes, tv_sec is 32-bit); /home/segin/freebsd/sys/kern/vfs_syscalls.c:2488-2493 (kernel zero-fills the st_*_ext words)
- **Defect:** On FreeBSD 14.x i386, time_t is 32-bit (x86/_types.h:80), so `struct timespec` is 8 bytes (tv_sec int32 + tv_nsec long). Because __STAT_TIME_T_EXT is defined for __i386__ (stat.h:155-157), the released i386 `struct stat` interleaves a zeroed 4-byte st_*_ext word BEFORE each timespec (stat.h:169-184). The real seconds values therefore sit at byte offsets 52/64/76/88. Substrate's freebsd13_timespec instead uses a 64-bit tv_sec (int64) with NO _ext word, placing tv_sec at offsets 48/60/72/84. The two layouts coincidentally both total 208 bytes (the substrate comment at freebsd_user.h:221-243 mistook this size match for a layout match), but the timestamp fields are shifted: for a normal positive timestamp the low 32 bits of substrate's int64 tv_sec land in the real struct's st_*_ext field and the high 32 bits (== 0) land in the real tv_sec. translate_stat_to_freebsd13() (freebsd_user.c:166-188) assigns native seconds into these misplaced fields. tv_nsec happens to stay aligned; only the seconds are corrupted.
- **Breaks:** Any FreeBSD i386 program calling stat/lstat/fstat/fstatat (routed through fstat_freebsd13=551 and fstatat_modern, freebsd_sys_fstat_v13/freebsd_sys_fstatat in freebsd_user.c) reads st_atime = st_mtime = st_ctime = st_birthtime = 0 (Thu Jan 1 1970). `make`, `ld`, `install -C`, tar/cpio incremental logic, and `ls -l` all rely on mtime: make rebuilds everything (or nothing) because every target and prerequisite reports the same epoch-0 mtime; timestamp-based caches and freshness checks are silently wrong. No crash, so it passes boot smoke tests while corrupting real workloads.

### P08. NetBSD signal frame built in obsolete sigcontext layout; handler receives NULL siginfo and a sigcontext where a ucontext_t is required
- **Substrate:** `sys/exec/perso/netbsd/netbsd_sig.c:157`  ·  struct-layout  ·  CONFIRMED
- **BSD reference:** /home/segin/netbsd/sys/arch/i386/include/frame.h:166-172 (struct sigframe_siginfo: sf_ra, sf_signum, siginfo_t *sf_sip, ucontext_t *sf_ucp, siginfo_t sf_si, ucontext_t sf_uc) + /home/segin/netbsd/sys/arch/i386/i386/machdep.c:663-685 (sendsig_siginfo sets frame.sf_sip=&sf_si, frame.sf_ucp=&sf_uc)
- **Defect:** netbsd_sendsig() (lines 157-202) builds the legacy compat_16 'struct netbsd_sigframe' = {sf_ra, sf_sig, sf_code, sf_scp, sf_sc(sigcontext)} and hands the handler (sig, code=0, scp) where scp points at a netbsd_sigcontext. Modern NetBSD (10.x, the version in the netbsd.img target) delivers EVERY signal through sendsig_siginfo, whose frame is sigframe_siginfo: the handler is entered as handler(int signum, siginfo_t *sf_sip, ucontext_t *sf_ucp). Substrate's arg2 is the integer 0 (sf_code) instead of a valid siginfo_t*, and arg3 points at a netbsd_sigcontext, not a ucontext_t. The sigcontext-style path (sendsig_sigcontext) lives in compat_16_machdep.c and is only used for ancient binaries. Additionally the saved-register layout (netbsd_user.h struct netbsd_sigcontext, gs/fs/es/ds/edi/esi/ebp/ebx/edx/ecx/eax/trapno/err/eip/...) does not match NetBSD's mcontext_t __gregs ordering (mcontext.h _REG_* : ESP sits at index 7 between EBP and EBX, UESP at 17), so even a corrected 3rd-arg pointer would expose a wrong register array.
- **Breaks:** A NetBSD binary that installs an SA_SIGINFO handler (libpthread's internal signal wrapper, or any crash handler doing handler(sig, info, uc)) dereferences arg2 -> reads through the integer 0 -> SIGSEGV at a near-NULL address on the very first signal. Handlers that inspect uc->uc_mcontext.__gregs[_REG_EIP] (JITs, GC safepoints, longjmp-from-signal via ucontext) read/write garbage offsets in a sigcontext, corrupting the resumed PC/registers. This is the identical defect the FreeBSD personality was explicitly rewritten to fix (freebsd_sig.c:16-25 comment about libthr faulting on a NULL info pointer).

### P09. ____shmctl50 wired at syscall 512 — real NetBSD number is 443, so SysV shmctl is unreachable (ENOSYS)
- **Substrate:** `sys/exec/perso/netbsd/netbsd_syscalls.h:296`  ·  wrong-syscall-number  ·  CONFIRMED
- **BSD reference:** /home/segin/netbsd/sys/kern/syscalls.master:933 ("443 STD MODULAR sysv_ipc { int|sys|50|shmctl(...) }"); confirmed by /home/segin/netbsd/sys/sys/syscall.h "#define SYS___shmctl50 443" (SYS_MAXSYSCALL is 507, so 512 is not a valid syscall at all)
- **Defect:** The header defines NETBSD_SYS_____shmctl50 = 512 and the table places the netbsd_sys_shmctl handler at index 512. NetBSD's time_t-64 shmctl (__shmctl50, sys|50|shmctl) is syscall 443, not 512 — in fact the entire NetBSD 10.x/current syscall table tops out at 507, so 512 corresponds to no syscall. A NetBSD binary's libc invokes int $0x80 with eax=443 for shmctl; index 443 is undefined in the substrate table, so it dispatches to ENOSYS, while the real handler sits dead at 512 where nothing ever calls it. semctl (____semctl50=442) and the other SysV IPC numbers are correct, making shmctl the lone broken one.
- **Breaks:** Any NetBSD program using System V shared memory that calls shmctl(shmid, IPC_STAT/IPC_SET/IPC_RMID, ...) — e.g. a server tearing down its shm segment on exit — issues syscall 443 and gets ENOSYS. shmget/shmat succeed but the segment can never be inspected or removed, so IPC_RMID cleanup silently fails and the program either errors out or leaks the segment.

### P10. sc_trapno/sc_err placed between sc_eax and sc_eip — FreeBSD ordering used for an OpenBSD sigcontext
- **Substrate:** `sys/exec/perso/openbsd/openbsd_user.h:19`  ·  struct-layout  ·  CONFIRMED

- **Defect:** struct openbsd_sigcontext lists sc_trapno (line 19) and sc_err (line 20) between sc_eax and sc_eip. OpenBSD (like its NetBSD parent) places sc_eip directly after sc_eax and puts sc_trapno/sc_err after sc_onstack/sc_mask. - **Breaks:** A signal handler or libc trampoline that reads the delivered sigcontext (SA_SIGINFO ucontext, setjmp/longjmp-from-handler, pthread cancellation, or any runtime unwinder that inspects sc_eip/sc_esp) reads sc_ecx/garbage where it expects sc_eip/sc_esp, producing wild control-flow on signal return.

### P11. getdents(390, __getdents30) returns Linux-layout dirent, not NetBSD struct dirent
- **Substrate:** `sys/exec/perso/perso_netbsd.c:405`  ·  struct-layout  ·  CONFIRMED

## MEDIUM

### P14. EOWNERDEAD/ENOTRECOVERABLE use FreeBSD values for NetBSD (shared table cannot be right for both)
- **Substrate:** `sys/arch/i386/syscall.c:60`  ·  errno-signo  ·  CONFIRMED
- **BSD reference:** /home/segin/netbsd/sys/sys/errno.h:176 (EOWNERDEAD 97), :177 (ENOTRECOVERABLE 98), :172 (ENOLINK 95), :173 (EPROTO 96); vs /home/segin/freebsd/sys/sys/errno.h:181 (EOWNERDEAD 96), :180 (ENOTRECOVERABLE 95)
- **Defect:** The same bsd_errno_xlate() serves PERS_FREEBSD, PERS_NETBSD and PERS_OPENBSD (dispatch at sys/arch/i386/syscall.c:524). It maps native EOWNERDEAD(130)->96 and ENOTRECOVERABLE(131)->95, which are FreeBSD's numbers. NetBSD, however, defines EOWNERDEAD=97 and ENOTRECOVERABLE=98; on NetBSD, 96 is EPROTO and 95 is ENOLINK. So a NetBSD binary that receives EOWNERDEAD (substrate returns -EOWNERDEAD from the robust-futex paths sys/kern/futex.c:1027 and :1250) is told errno=96=EPROTO, and ENOTRECOVERABLE becomes 95=ENOLINK. A single flat table cannot be simultaneously correct for FreeBSD (96/95) and NetBSD (97/98); the translation must branch on p->id for these two robust-mutex errnos.
- **Breaks:** A NetBSD program using robust pthread mutexes (or otherwise reaching an abandoned-owner path) gets EOWNERDEAD/ENOTRECOVERABLE from the kernel. Instead of the expected 97/98 it receives 96/98->96/95, i.e. EPROTO/ENOLINK. Robust-mutex recovery code that checks `errno == EOWNERDEAD` never fires, so the mutex is not marked consistent and the program either aborts or deadlocks.

### P15. fbsd_lflag termios table uses wrong FreeBSD bit values for TOSTOP and FLUSHO
- **Substrate:** `sys/exec/perso/compat.c:1363`  ·  flag-translation  ·  CONFIRMED
- **BSD reference:** /home/segin/freebsd/sys/sys/_termios.h:175 (TOSTOP 0x00400000), :177 (FLUSHO 0x00800000)
- **Defect:** The fbsd_lflag translation table encodes TOSTOP as FreeBSD bit 0x00008000 and FLUSHO as 0x00010000.
